### 需要重点注意的三个硬件约束（新发现）

| # | 问题 | 影响 | 处理方式 |
|---|------|------|----------|
| **A** | **UART0 与 USB-C 烧写口共用**（IO43/IO44 ↔ CH340C） | Parker 的数据线接上后，**无法同时用 USB 串口监视器调试** | HY2.0 接头可拔插；调试时拔掉 Parker 线。另做屏上调试日志区 |

### 2.1 引脚占用实况

800×480 的 RGB 并口几乎吃掉了 ESP32-S3 的全部引脚：

| 用途 | 引脚 |
|------|------|
| RGB 数据（16 根） | IO14/21/47/48/45（R）、IO9/46/3/8/16/1（G）、IO15/7/6/5/4（B） |
| 时序 | DE=IO41、HSYNC=IO39、VSYNC=IO40、**PCLK=IO0（同时是 BOOT 引脚）** |
| 背光 | IO2 |
| 触摸 / I2C | IO19、IO20 |
| microSD (SPI) | IO10/11/12/13 |
| 喇叭 (I2S) | IO17/18/42 |
| **UART0** | **IO43 (TX) / IO44 (RX)** ← 与 CH340C USB-C 共用 |
| **唯一空闲 GPIO** | **IO38** |

> **重要：** ESP32-S3 的原生 USB 引脚（IO19/IO20）在本板被占用于 I2C，所以**没有 USB-CDC 可用**，只能走 CH340C→UART0。这就是约束 A 的根因。

### 4.2 功能 1.1 — 土壤水分 0–4096 的含义与百分比换算

**Parker 已确认（2026-09-11）：** 下列三点取代此前的待确认清单。

| # | 原问题 | Parker 答复 | 界面侧结论 |
|---|--------|-------------|------------|
| 1 | 4096 是原始值还是已换算值？ | **原始 ADC 计数**；可以降采样，但会损失精度 | 协议**保持 0–4095 满量程**，由界面换算成 %；不要在硬件侧先压成 0–1024 或 0–100 |
| 2 | 探头类型？ | 三路独立传感器，见下表 | 功能 1.1 显示的是**电容式土壤水分**，不是空气湿度；水位走浮球开关 |
| 3 | 标定 / 阈值？ | 约每 **30 s** 测一次；与预定阈值比较（目标约 **55%**）；**ADC 1844–2457 ≈ 土壤水分 45–60%** | 界面按该两点标定显示 %；告警带 = 45–60% |

#### 三路传感器（已确认）

| 传感器 | 类型 | 数据形态 | 谁用 |
|--------|------|----------|------|
| **土壤水分** | Capacitive Moisture Sensor（电容式） | 12 位 ADC 原始计数 **0–4095**（文档里说的 0–4096 即此满量程） | 功能 1.1 主显示 + `moisture_alert` |
| **空气湿度** | Resistive Humidity Sensor（电阻式） | 尚未纳入当前 UI 需求 | **本版界面不显示**；若要上屏，另开字段（见 §5.2） |
| **水位** | Float Switch Level Sensor（浮球开关） | 开关量 0/1 | 功能 3 低水位全屏告警 |

术语对齐：需求原文写「湿度」，硬件上对应的 0–4096 通道是 **moisture（土壤/基质水分）**。界面主标签改为 **「水分 / MOISTURE」**，避免和电阻式空气湿度混淆。

#### 为什么是 0–4096？

**4096 = 2¹²**，即 **12 位 ADC 满量程**。有效整数范围是 **0–4095**（4096 个台阶）。这不是百分比。

Parker 明确可以降采样（例如右移 2 位变成 10 位 0–1023，或直接映射成 0–100 再上传）。**不要这么做：** 每次降采样都丢掉量化台阶，45–60% 工作区本来就只有约 **613 个原始计数**（2457−1844），再压缩后阈值比较会变钝。正确分工是：

- Parker：**原样上报** `moisture_raw`（0–4095）
- 界面：换算成整数百分比给操作者看

#### 换算公式（按 Parker 给出的工作区两点）

Parker 给出的数字与线性满量程映射一致：

| ADC raw | 土壤水分 | 验算 |
|---------|----------|------|
| 1844 | 45% | 1844 / 4095 ≈ 45.03% |
| ≈ 2252 | **55%（控制目标）** | 4095 × 0.55 ≈ 2252 |
| 2457 | 60% | 2457 / 4095 = **60.00%** |

因此界面采用：

```c
// moisture_raw: 0..4095
static inline int moisture_to_percent(int raw) {
    if (raw < 0)    raw = 0;
    if (raw > 4095) raw = 4095;
    return (int)((raw * 100.0f) / 4095.0f + 0.5f);
}
```

| 参数 | 含义 | 已确认值 |
|------|------|----------|
| `raw` | 电容式水分探头的 12 位 ADC 原始计数 | 0–4095 |
| 工作区下限 | 水分过低告警线 | **45% / ADC 1844** |
| 控制目标 | Parker 比较用的预定阈值 | **约 55% / ADC ≈ 2252** |
| 工作区上限 | 水分过高告警线 | **60% / ADC 2457** |

告警语义（仍由 **Parker 固件**比较后上报，界面不自行改写）：

| `moisture_alert` | 含义 | 建议判据（Parker 侧） |
|------------------|------|----------------------|
| 0 | 正常 / 无变化 | 落在 45–60%（1844–2457） |
| 1 | 水分太高 | raw > 2457（> 60%） |
| 2 | 水分过低 | raw < 1844（< 45%） |

> **极性说明：** 常见裸电容探头是「越干 ADC 越高」。Parker 给出的 1844→45%、2457→60% 是**正向**（越大越湿），与 `raw / 4095 × 100` 一致。界面按此实现。若 Parker 实际输出的是未取反的裸电容值，需在**硬件侧**先取反再上报，不要让界面猜。

**ADC 精度提醒（给 Parker）：** 30 s 采样已经很低频，单次毛刺会被界面钉住半分钟。建议在 Parker 侧对每次上报做 8–16 次滑动平均（或中值），再与 1844/2457 比较。

#### 采样周期对界面的影响

水分**大约每 30 秒**才更新一次。这改变了 v2.0 里「telemetry 2–5 Hz」的假设：

| 项 | 做法 |
|----|------|
| 界面水分数字 | 收到新值才刷新；两次采样之间**保持上次读数**，不要每秒闪烁 |
| 条形图工作区 | 在 45% 与 60% 处画刻度，55% 处画目标标记 |
| 通信心跳 | **水分更新慢 ≠ 链路断了**。Parker 仍应按约 **1 Hz** 重复发送 telemetry（水分字段带上次读数），这样界面才能用 2 s 超时检测断线。若硬件只能 30 s 发一帧，须把超时改成 **≥ 60 s** |

#### 界面展示建议

```
┌──────────────────────────────┐
│   水 分  MOISTURE             │
│        5 5 %                  │   ← 大号数字，主显示
│   ▓▓▓▓▓▓┃▓▓░░░░░░             │   ← 条形图；┃ = 55% 目标
│        45%        60%         │   ← 工作区刻度
│   状态：正常                   │   ← 由 moisture_alert 驱动
│   RAW 2252                    │   ← 小字，调试用，发布版可隐藏
└──────────────────────────────┘
```

- 主显示保留**整数百分比**；30 s 一变，不会抖
- `moisture_alert` = 1 / 2 时用**颜色 + 文字**双重提示（过高 / 过低）
- 空气湿度（电阻式）本版不上屏；确认要显示后再加

#### 仍待双方拍板（已不再阻塞换算公式）

1. 电阻式空气湿度是否要出现在界面上？若要，Parker 提供该通道的数据形态（也是 ADC，还是已是 %RH）。
2. 通信心跳：Parker 能否在两次 30 s 水分采样之间，以 ~1 Hz 重发上次 telemetry？建议能。

### 4.4 功能 3 — 低水位全屏告警

| 项 | 评估 |
|----|------|
| 可行性 | ✅ 完全可行 |
| 实现 | 全屏 `lv_obj` overlay（800×480，置顶）+ `lv_timer` 每 500 ms 切换红/黑底色与文字显隐 |
| 消警 | overlay 自身接收点击事件，`LV_EVENT_CLICKED` → 隐藏 overlay，置 `alarm_dismissed = true` |
| 再次告警 | 收到 `water_level` 从 0→1 的**跳变**时重置 `alarm_dismissed = false`，重新闪烁 |
| 硬件 → 界面 | `1` = 低水位，`0` = 水位正常 |

**⚠️ 电容触摸误触风险（本硬件特有，必须处理）**

雾培箱在喷雾时，水雾或凝露落在电容屏上会产生**幽灵触摸**。如果直接「触摸任意位置即消警」，告警可能在用户还没看到的瞬间就被一滴水自己消掉了。

**建议的三层防护（任选或组合）：**

| 方案 | 说明 | 推荐度 |
|------|------|--------|
| **最短闪烁时长** | 告警出现后强制闪烁 ≥ 3 秒，期间忽略所有触摸 | ⭐⭐⭐ 必做 |
| **要求确认区点击** | 不是「任意位置」，而是屏幕中央一块大按钮（如 400×120）「我已知晓 / ACKNOWLEDGE」 | ⭐⭐⭐ 强烈建议 |
| **需连续两次触摸** | 300 ms–2 s 内两次点击才消警 | ⭐⭐ 备选 |

> 需求原文是「触摸屏幕任意位置停止闪烁」。功能上可以照做，但**从可靠性角度我建议改成中央大按钮**。这块请团队讨论定稿。

**另外两点：**

- **消警 ≠ 解除故障。** 界面停止闪烁只是视觉降噪，Parker 侧的实际低水位状态不受影响。消警后建议在主界面保留一个常驻的红色「低水位」状态条，直到 `water_level` 回到 0。
- **可选的声音告警：** 本板有 SPK 接口（NS4168 I2S 功放）。雾培箱常无人值守，接一个小喇叭做蜂鸣提示比纯视觉闪烁有效得多。Basic 版**没有**板载蜂鸣器（Advance 版才有），需外接。

## 5. JSON 通信协议（v1 草案）

### 5.1 物理层

| 项 | 值 |
|----|-----|
| 接口 | CrowPanel **UART0 口**（HY2.0-4P），IO43=TX / IO44=RX |
| 波特率 | **115200**，8N1 |
| 电平 | **3.3 V TTL** |
| 接线 | Parker.TX → Panel.RX(IO44)、Parker.RX → Panel.TX(IO43)、**GND ↔ GND 必须共地** |
| 编码 | UTF-8 |
| 帧格式 | **NDJSON**，每行一个 JSON 对象，以 `\n` 结束 |

> **⚠️ 电平匹配：** CrowPanel 的 UART 是 **3.3 V**。如果 Parker 用的是 Arduino Uno / Mega（5 V 逻辑），**必须加电平转换模块**，直连有烧毁 ESP32-S3 的风险。如果 Parker 也用 ESP32 / STM32（3.3 V），可以直连。**这一条请务必在接线前确认。**

> **⚠️ 供电：** UART0 口支持 5 V 输入供电，理论上 Parker 板可以给屏供电。但 7 吋屏带背光需要 **5 V / 2 A**，请确认 Parker 侧电源有这个余量；**更稳妥的做法是给屏配独立的 5 V/2 A 电源，两边只共 GND 和 TX/RX 三根信号线。**

### 5.2 硬件 → 界面（Telemetry）

建议 **约 1 Hz 心跳上报**（重复上次水分读数即可），告警状态跳变时立即补发一帧。电容式水分探头本身约每 **30 s** 才采一次新样；字段名从 v2.0 的 `humidity_*` 更正为 `moisture_*`，与 Parker 确认的传感器类型对齐。

```json
{"type":"telemetry","moisture_raw":2252,"moisture_alert":0,"water_level":0,"temperature_c":22.0,"setpoint_c":22,"pump":1}
```

| 字段 | 类型 | 取值 | 说明 |
|------|------|------|------|
| `type` | string | `"telemetry"` | 消息类型 |
| `moisture_raw` | int | 0–4095 | 电容式水分探头 **12 位 ADC 原始计数**（不要降采样） |
| `moisture_alert` | int | 0 / 1 / 2 | 0 = 正常，**1 = 水分太高**（>60% / >2457），**2 = 水分过低**（<45% / <1844） |
| `water_level` | int | 0 / 1 | 浮球开关：0 = 水位正常，**1 = 低水位** |
| `temperature_c` | float | 必须（已确认） | 当前实测温度（°C） |
| `setpoint_c` | number | 必须（v1.3 新增） | Parker 实际持有的温度设定值（15–30），屏重启后据此对齐 |
| `pump` | int | 必须（已确认），0 / 1 | 水泵实际运行状态，用于界面 Switch 与硬件对齐 |
| `humidity_rh` | int/float | 可选，暂不发 | 电阻式空气湿度；本版 UI 忽略。若后续要上屏再启用 |

> `pump` 字段是新增建议：界面重启或通信恢复后，需要知道水泵**真实**状态，否则 Switch 显示可能与实际相反。`setpoint_c` 是同一个道理的温度版本 —— 屏没有掉电保存，不回读设定值就会在重启后显示自己的默认 22 °C 而与箱体不符。
>
> v2.0 草稿里的 `humidity_raw` / `humidity_alert` **作废**，联调请改用 `moisture_*`。若 Parker 固件已按旧名发出，界面可临时两种都认，但定稿只保留新名。

### 5.3 界面 → 硬件（Command，仅在用户点「确认」后发送）

**水泵：**

```json
{"type":"command","pump":1}
```

| `pump` | 含义 |
|--------|------|
| 0 | 无变化 |
| **1** | **打开水泵** |
| **2** | **关闭水泵** |

**温度：**

```json
{"type":"command","temperature":{"changed":1,"new_temp":23}}
```

| `changed` | 含义 |
|-----------|------|
| 0 | 无改动（`new_temp` 可忽略） |
| **1** | **有改动**，读取 `new_temp`（整数 15–30，单位 °C） |

### 5.4 与原始需求的对照

需求里定的数值语义**一个都没改**，只是加了字段名和 `type` 便于解析扩展：

| 原始需求 | 协议字段 | 数值语义 |
|----------|----------|----------|
| 1.2 界面→硬件 水泵 | `pump` | 1=开 / 2=关 / 0=无变化 ✅ 一致 |
| 1.3 硬件→界面 水分告警 | `moisture_alert` | 1=太高 / 2=过低 / 0=无变化 ✅ 语义一致（字段更名） |
| 2.1 界面→硬件 温度 | `temperature.changed` + `.new_temp` | 1=有改动 / 0=无改动 ✅ 一致 |
| 3.1 硬件→界面 水位 | `water_level` | 1=低水位 / 0=正常 ✅ 一致 |

### 5.5 通信规则

1. 一行一个 JSON，`\n` 结尾；单条长度建议 < 256 字节。
2. 用户点「取消」→ **不发送任何报文**（语义等价于 `pump=0` / `changed=0`）。
3. **ACK（建议 v1.1 加入）：** Parker 收到 command 后回 `{"type":"ack","ok":true}`。界面在 1 秒内未收到 ACK 时提示「指令未确认」，避免用户以为已生效。
4. **通信超时：** 界面若 **2 秒**内未收到任何 telemetry，在状态栏显示「⚠ 通信中断」，并把水分/温度数值置灰为 `--`，**不要继续显示过期的旧值**。这要求 Parker 以约 1 Hz 心跳重发；水分数字本身可以 30 s 不变。若做不到 1 Hz 心跳，超时改为 ≥ 60 s。
5. **解析容错：** 收到非法 JSON 时丢弃该行并继续，不得复位或卡死。

## 6. 界面交互状态机

### 6.1 水泵 Switch

```
[confirmed = OFF]
      │ 用户拨动 Switch 到 ON（LV_EVENT_VALUE_CHANGED，仅改变外观）
      ▼
[pending = ON]
      │ 手指抬起（LV_EVENT_RELEASED）
      ▼
  ┌─ 弹出模态确认框 ─┐
  │ 确认              │ 取消
  ▼                   ▼
发送 {"pump":1}     Switch 回弹到 OFF
confirmed = ON      pending 丢弃
```

### 6.2 温度 Slider

```
[confirmed = 22°C]
      │ 用户拖动到 25（实时显示 25，但不发送）
      ▼
[pending = 25]
      │ 手指抬起（LV_EVENT_RELEASED）
      ▼
  ┌─ 弹出模态确认框 ─┐
  │ 确认                      │ 取消
  ▼                           ▼
发送 {"changed":1,          Slider 回弹到 22°C
      "new_temp":25}
confirmed = 25
```

### 6.3 低水位告警

```
water_level: 0 ──────────────► 正常主界面

water_level: 0 → 1 跳变
      │ alarm_dismissed = false
      ▼
全屏闪烁「Low Water」（500 ms 周期）
      │ 强制闪烁 ≥ 3 秒，期间忽略触摸   ← 防误触
      ▼
用户点击中央 ACKNOWLEDGE 按钮
      │ alarm_dismissed = true
      ▼
返回主界面，顶部保留常驻红色「低水位」状态条
      │
      ├─ water_level 回到 0 ──► 状态条消失
      └─ water_level 再次 0→1 跳变 ──► alarm_dismissed = false，重新闪烁
```

```
┌────────────────────────────────────────────────────────────────┐
│  AUTO HYDRO                              ● LINK OK             │  ← 状态栏：品名 + 链路，无日期
├──────────────────────────┬─────────────────────────────────────┤
│                          │                                     │
│   水 分  MOISTURE        │   目标温度  TARGET TEMP             │
│                          │                                     │
│      5 5 %               │        2 3 °C                       │
│   ▓▓▓▓▓▓┃▓▓░░░░░░        │   ├──┼──┼──┼──●──┼──┼──┼──┤        │
│   45%      60%  正常     │   15                        30      │
│                          │   实测  2 2 °C                      │
│                          │                                     │
├──────────────────────────┴─────────────────────────────────────┤
│                                                                │
│   水 泵  PUMP        ┌─────────┐                               │
│                      │  O—— ON │        水位  WATER: 正常       │
│                      └─────────┘                               │
└────────────────────────────────────────────────────────────────┘
```

**状态栏约定：**

| 项 | 做法 |
|----|------|
| 产品名 | 左上角固定 **AUTO HYDRO**（本系统无 steamer / 雾化器，不用 Aeroponic Life Support） |
| 链路 | 右侧只显示 **LINK OK** / **通信中断** |
| 日期时间 | **不显示**。设备不联网，也**不做校时界面**；离线 MCU 的时钟会漂，显示日期只会误导 |

**「古早但功能完整、易用性好」的具体做法：**

| 要素 | 建议 |
|------|------|
| 配色 | 深灰底 + 浅灰立体边框 + 高对比黄/绿数字，仿传统工业仪表盘 |
| 按钮 | 带 2–3 px 明暗边的**凸起立体感**（LVGL `border` + `shadow` 即可），按下时变凹陷 |
| 数字 | 大号等宽字体（Montserrat 48/72），水分与温度用最大号 |
| 控件尺寸 | 所有可点区域 **≥ 60 × 60 px**（手指 + 可能戴手套操作） |
| 动效 | **全部关闭**。既符合古早风格，又规避 RGB 面板刷新率限制 |
| 中英文 | 中文需嵌入字体子集（只打包用到的那几十个字），4MB Flash 省着用 |

> TN 面板可视角度较窄（不如 IPS），安装时请让屏幕正对操作者常站的位置和高度。

## 10. 结论

1. **方案可行，硬件选型合适。** CrowPanel 7" ESP32-S3 的算力、800×480 分辨率、GT911 电容触摸和 LVGL 生态，完全支撑这三项功能；离线串口 JSON 也是它的典型用法。
2. **界面框架只能用 LVGL**，Qt 在这块板上不可行（无 Linux）。v1.0 文档中的 Qt 选项作废。
3. **水分 0–4096 已由 Parker 确认为 12 位 ADC 原始计数。** 协议保持满量程（降采样会丢精度）。界面用 `raw / 4095 × 100` 显示整数百分比；工作区 **45–60% = ADC 1844–2457**，控制目标约 **55%**。探头是电容式水分传感器，约 30 s 采样一次；空气湿度是另一路电阻式探头，本版不上屏；水位是浮球开关。
4. **三个必须提前处理的硬件约束：** UART0 与烧写口共用（影响调试流程）；可用 GPIO 几乎为零（所以传感器全归 Parker，符合分工）；无防护等级 + 电容触摸（雾培环境需外壳，告警消除需防误触）。
5. **「古早风格」是正向选择**，不只是审美偏好 —— 4MB Flash 有限、RGB 面板刷新率有限，极简高对比的工业风既省资源又提升易用性。
6. **下一步：** 按已冻结的 `docs/INTEGRATION_GUIDE_zh.md` **两端并行开发**。接线注意：3.3 V 直连；5 V 供电不要进 BAT 口。
